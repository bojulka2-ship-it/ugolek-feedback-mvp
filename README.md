# Кофейня «Уголёк» — MVP формы обратной связи

Одностраничное мини-приложение для сбора отзывов гостей кофейни. Все отзывы попадают в **единое общее хранилище** — централизованный сбор в одном месте вместо бумажных карточек и комментариев в соцсетях.

## Быстрый старт

Требование: Node.js (проверено на v24).

```bash
node server.js
```

Открыть в браузере: `http://localhost:3000`

Порт и хост настраиваются переменными окружения: `PORT` (по умолчанию 3000) и `HOST` (по умолчанию `127.0.0.1` — только локальный доступ; для доступа с других устройств запускайте с `HOST=0.0.0.0`). Оконный лимит частоты отправки отзывов — `RATE_LIMIT_WINDOW_MS` (по умолчанию 60000, не более 10 POST в минуту с одного адреса).

## Возможности

- Оценка визита **1–5 звёздами** (клик / клавиатура, hover-подсветка).
- Поле «Что понравилось из меню» и комментарий (необязательные).
- Список отзывов — новые сверху, переживает перезапуск сервера.
- Защита от мусорных текстов: повторяющиеся символы, «тарабарщина» из-за неверной раскладки, подсказки при вводе (поле «меню» блокируется жёстко).
- Адаптивность от 360 px, без внешних запросов и зависимостей.

## Технологии

Никаких npm-пакетов и внешних ресурсов: **только стандартная библиотека Node.js** (`http`, `fs`, `path`) + инлайновые HTML/CSS/JS.

## Хранение данных

- Отзывы сохраняются в файле **`reviews.json`** (централизованно, атомарная запись).
- Файл исключён из git (`.gitignore`) — в репозиторий попадают только демо-данные, без реальных персональных данных.

## Структура

## API (для разработки)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | страница |
| GET | `/api/reviews` | список отзывов |
| POST | `/api/reviews` | `{ rating, menu, comment }` → 201, либо 4xx/413 при нарушениях |

## Ограничения проекта

Демо локальное (localhost), без СУБД, авторизации, писем, CRM, внешних AI API и платного хостинга. Полный список — в `02_Ограничения_и_материалы.md`.

## Статус

MVP готов к демонстрации. **Решение «готов к публикации» пока не утверждено** — см. `AUDIT_REPORT.md` (осталось: rate-limit на POST и живое браузерное демо сценариев K5/K8).

## Как внести вклад

Любые предложения приветствуются. Порядок работы:

1. **Обсудите идею** — сначала напишите о баге или фиче (issue), прежде чем писать большой код.
2. **Создайте ветку** от `master` и делайте изменения в ней.
3. **Проверьте перед PR:**
   - `node --check server.js` — синтаксис сервера;
   - smoke-тест: `node server.js`, затем `GET /` → 200 и валидный `POST /api/reviews` → 201;
   - не приносите в проект внешние npm-зависимости без явной необходимости (проект zero-dependency);
   - не коммитьте `reviews.json` — это личные данные гостей (есть в `.gitignore`).
4. **Откройте pull request** с понятным описанием изменений и того, как проверить.

Сообщения коммитов — по Conventional Commits (`feat`, `fix`, `docs`, `chore`, …) на русском или английском, с кратким описанием сути.
