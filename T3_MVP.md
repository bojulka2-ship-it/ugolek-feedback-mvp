# ТЗ на MVP — кейс FORMA «Кофейня Уголёк»

## 1. Бизнес-проблема

Кофейня «Уголёк» собирает отзывы гостей разрозненно: бумажные карточки на столиках и комментарии в соцсетях, без единой структуры. Владельцу не видна общая картина: что гостям нравится, а что нет, какие позиции меню хвалят или ругают чаще всего.

Клиент подтвердил ключевое требование: «все отзывы в одном месте» — это **централизованный сбор**: отзывы из разных браузеров/устройств должны попадать в единое общее хранилище (фиксируется в «01_Текущий процесс.md», ограничения актуализированы в «02_Ограничения_и_материалы.md»).

## 2. Цель и метрики успеха

**Цель:** за один учебный спринт получить работающий прототип формы обратной связи, который централизованно собирает отзывы в единое хранилище и позволяет владельцу по списку отзывов понять общую картину.

| Метрика | Критерий успеха |
|---|---|
| Собрано отзывов | ≥ 3 валидных отзыва за пилот (проверка на 2–4 ответах) |
| Полнота данных | 100% собранных отзывов имеют оценку 1–5 |
| Централизованность | Один и тот же отзыв виден из двух разных браузеров одной машины |
| Устойчивость хранения | Отзывы сохраняются после перезапуска сервера (файл `reviews.json`) |
| Анализируемость | По списку можно назвать минимум одну позицию меню, которую упоминают чаще других |
| Работоспособность демо | Работает локально (localhost) без интернета и платного хостинга |

## 3. Пользователи и основной сценарий

- **Гость кофейни** — оставляет отзыв через форму (единственный пользователь MVP).
- **Владелец** — просматривает собранные отзывы в списке на той же странице (отдельного входа/роли нет).

**Основной сценарий (счастливый путь):**
1. Сервер запущен (`node server.js`), гость открывает `http://localhost:3000`.
2. Ставит оценку визита (1–5), заполняет «Что понравилось из меню» и/или комментарий.
3. Нажимает «Оставить отзыв».
4. Отзыв сохраняется в общее хранилище (`reviews.json`) и появляется в списке на той же странице без перезагрузки (новые сверху).
5. Отзыв виден из любого другого браузера той же машины; после перезапуска сервера остаётся на месте.

## 4. Что входит и не входит в MVP

**Входит:**
- минимальный локальный сервер на Node.js (только стандартная библиотека, без npm/внешних пакетов);
- форма из трёх запрошенных полей: оценка визита, «Что понравилось из меню», комментарий;
- валидация обязательной оценки;
- централизованное хранение отзывов в файле `reviews.json`;
- отображение всех отзывов в простом списке на той же странице;
- адаптивный интерфейс 360 px — desktop;
- брендинг по доступным материалам (текст-логотип «Кофейня Уголёк», цвета: оранжевый/коричневый/зелёный).

**Не входит (функций клиент не просил):**
- авторизация, CRM, внешние интеграции и API;
- СУБД и внешние сервисы/хостинг;
- админ-панель, редактирование и удаление отзывов;
- аналитика и графики, средняя оценка, рейтинг позиций;
- модерация, фильтры, поиск, пагинация;
- экспорт/выгрузка отзывов;
- отправка писем/сообщений, уведомления;
- загрузка файлов, генерация PDF;
- обработка персональных данных и публичный запуск.

## 5. Функциональные требования

| № | Требование |
|---|---|
| Ф1 | Сервер запускается командой `node server.js` и обслуживает страницу на `http://localhost:3000` |
| Ф2 | Страница содержит форму обратной связи с тремя полями и кнопкой отправки |
| Ф3 | Оценка визита выбирается из 5 целочисленных значений (звёзды 1–5) |
| Ф4 | Поля «Что понравилось из меню» и «Комментарий» необязательны |
| Ф5 | `GET /` отдаёт HTML-страницу (форма + список) |
| Ф6 | `GET /api/reviews` возвращает JSON-список всех отзывов из общего хранилища |
| Ф7 | `POST /api/reviews` принимает `{ rating, menu, comment }`, валидирует и сохраняет отзыв в `reviews.json` |
| Ф8 | После успешной отправки отзыв появляется в списке без перезагрузки страницы (fetch) |
| Ф9 | Список показывает все отзывы из общего хранилища, новые сверху |
| Ф10 | Каждый отзыв в списке показывает: оценку, «что понравилось из меню», комментарий, дату |
| Ф11 | Текст отзывов выводится безопасно (экранируется) |
| Ф12 | Форма корректно работает и выглядит от ширины экрана 360 px и на десктопе |
| Ф13 | Отзывы сохраняются в файле `reviews.json` и переживают перезапуск сервера |

## 6. Поля, варианты значений и валидация

### Поля формы

| Поле | Тип | Обязательность | Варианты/ограничения |
|---|---|---|---|
| Оценка визита | радио-звёзды (1–5) | да | целое число 1, 2, 3, 4, 5; по умолчанию ничего не выбрано |
| Что понравилось из меню | текст (однострочный) | нет | до 100 символов; пробелы по краям обрезаются |
| Комментарий | textarea | нет | до 500 символов; пробелы по краям обрезаются |
| Отправка | кнопка «Оставить отзыв» | — | активна всегда; отправка блокируется при ошибке валидации |

### Правила валидации

1. Оценка не выбрана → отзыв **не сохраняется**, показывается сообщение «Укажите оценку визита».
2. Длина поля превышена → ограничение на уровне поля (`maxlength`) и/или сообщение об ошибке.
3. Пустые текстовые поля после обрезки — допустимо (разрешён отзыв только с оценкой).
4. Сервер повторяет проверку оценки (ответ 400 при отсутствии/некорректной оценке) — защита от прямой отправки к API.

### Хранимая запись (массив в `reviews.json`)

```
{ id, rating (1–5), menu (строка), comment (строка), createdAt (дата ISO) }
```

## 7. Состояния интерфейса

| Состояние | Описание |
|---|---|
| Пустой список | Заглушка «Отзывов пока нет» — до первого отзыва |
| Форма начальная | Все поля пустые, оценка не выбрана |
| Отправка | Кнопка блокируется на время запроса |
| Ошибка валидации | Сообщения «Укажите оценку визита» / об ошибке длины; отзыв не сохраняется |
| Успешная отправка | Форма очищается, «Спасибо за отзыв!», отзыв появляется вверху списка |
| Список с отзывами | Отзывы из общего хранилища, новые сверху |
| Сервер недоступен / ошибка сохранения | Сообщение «Не удалось сохранить отзыв», введённые данные не теряются, страница не ломается |
| Ошибка чтения списка | Краткое сообщение об ошибке вместо списка («Проверьте, что сервер запущен») |

## 8. Ограничения, риски и открытые вопросы

### Ограничения проекта (актуализировано, см. «02_Ограничения_и_материалы.md»)

- Без платного хостинга (только localhost), без СУБД и внешних сервисов, без авторизации, писем/сообщений, CRM, загрузки файлов, PDF, внешних AI API.
- Сервер на Node.js, только стандартная библиотека (`http`, `fs`), без npm и внешних пакетов.
- Только вымышленные данные; без токенов/паролей/ключей в репозитории; без чувствительных данных. `reviews.json` не коммитится (в `.gitignore`).
- Браузеры: актуальные Chrome, Edge, Safari; минимальная ширина 360 px.
- Логотипа и фото интерьеров нет → текст-логотип «Кофейня Уголёк».

### Риски

| Риск | Митигация |
|---|---|
| На машине демонстрации должен быть установлен Node.js | Зафиксировано в инструкции по запуску; версия проверена (v24) |
| Сервер должен быть запущен для сбора отзывов | Зафиксировано; без сервера страница показывает состояние «сервер недоступен», не падает |
| Конкурентная запись в файл | Некритично при 2–4 отзывах; запись атомарная (временный файл + переименование) |
| Нет бэкапа хранилища | Принято для MVP |
| Хранилище централизовано только в пределах localhost (не интернет) | Соответствует ограничению «демонстрация проходит локально в браузере» |
| Вымышленные данные могут быть приняты за реальные | Пометка в публикации/презентации, что данные тестовые |

### Открытые вопросы

1. Нужна ли владельцу кнопка очистки списка отзывов? Клиент не просил — по умолчанию исключено.
2. Формат даты в списке: `ДД.ММ.ГГГГ` или с временем? По умолчанию — дата.
3. Допустим ли отзыв только с оценкой без текста? По умолчанию — да.
4. Показывать ли среднюю оценку над списком? Клиент просил только список — по умолчанию исключено.

## 9. Проверяемые критерии приёмки

| № | Критерий (проверяемо) |
|---|---|
| K1 | `node server.js` запускает сервер; `http://localhost:3000` открывается в Chrome, Edge и Safari без интернета |
| K2 | Форма содержит ровно запрошенные поля: оценка 1–5, «Что понравилось из меню», «Комментарий», кнопка отправки |
| K3 | Отзыв без оценки не сохраняется, показывается «Укажите оценку визита» |
| K4 | После отправки валидного отзыва он мгновенно появляется вверху списка с оценкой, текстом и датой |
| K5 | Отзыв из одного браузера (например, Chrome) виден в другом (Edge) той же машины — централизованность |
| K6 | Отзыв сохраняется в `reviews.json` и остаётся после перезапуска сервера |
| K7 | Список отображает все сохранённые отзывы, новые сверху |
| K8 | Интерфейс корректен на ширине 360 px и на десктопе |
| K9 | Пилот завершается успешно: 2–4 отзыва собраны и видны в одном списке |
| K10 | На странице нет внешних запросов/зависимостей; код не содержит ключей и реальных персональных данных; `reviews.json` в `.gitignore` |

## Резюме

**Ключевые решения:** централизованный сбор подтверждён клиентом; MVP — локальный Node.js-сервер (стандартная библиотека, без npm) + HTML/CSS/JS; общее хранилище — файл `reviews.json` (вместо localStorage); «в одном месте» = единое хранилище для всех браузеров машины демонстрации; цвета бренда + текст-логотип «Кофейня Уголёк».

**Исключённые из MVP функции:** авторизация, CRM, внешние интеграции и API, СУБД и внешний хостинг, админ-панель, редактирование/удаление отзывов, аналитика и средняя оценка, экспорт, уведомления, обработка персональных данных и публичный запуск.

**Открытые вопросы:** очистка отзывов владельцем; формат даты; допустимость отзыва только с оценкой; показ средней оценки.
